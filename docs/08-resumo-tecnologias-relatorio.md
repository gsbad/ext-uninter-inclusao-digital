## Tecnologias Utilizadas

A aplicação foi desenvolvida segundo o padrão arquitetural MVC (Model-View-Controller), estruturada como um sistema monolítico com renderização de páginas realizada no próprio servidor. Essa escolha dispensa a existência de uma API separada consumida por um front-end independente, concentrando toda a lógica de apresentação, negócio e persistência em um único projeto, o que simplifica a manutenção e a evolução do sistema ao longo do desenvolvimento.

No backend, foi utilizada a linguagem Java, na versão 21, em conjunto com o framework Spring Boot (versão 3), que fornece os módulos responsáveis pelo roteamento de requisições (Spring MVC), pela persistência de dados (Spring Data JPA) e pela validação de formulários (Spring Validation). A renderização das páginas é feita pelo motor de templates Thymeleaf, integrado nativamente ao Spring Boot. O frontend é composto por HTML5, CSS3 e pelo framework Bootstrap 5, incluindo o pacote de ícones Bootstrap Icons, ambos incorporados diretamente ao backend por meio de bibliotecas WebJars, o que dispensa a dependência de serviços externos de distribuição de conteúdo durante a execução da aplicação. O armazenamento de dados é realizado em um banco de dados relacional PostgreSQL, com o esquema de banco versionado e migrado automaticamente por meio da ferramenta Flyway. O gerenciamento de dependências e o processo de build do projeto são realizados com Maven, e a qualidade do código é verificada por testes automatizados desenvolvidos com JUnit 5, Mockito e Testcontainers, este último responsável por validar a aplicação contra uma instância real de banco de dados PostgreSQL. A aplicação foi containerizada com Docker, e a implantação em ambiente de homologação foi realizada na plataforma Render.

A seleção dessas tecnologias baseou-se em critérios de simplicidade, facilidade de manutenção, acessibilidade e adequação ao escopo de um projeto de Atividade Extensionista. A adoção de uma arquitetura monolítica com renderização no servidor reduz a complexidade de manutenção e a dependência de processamento no navegador do usuário final, característica especialmente relevante considerando que o público-alvo da aplicação são pessoas idosas, que podem utilizar dispositivos e navegadores mais simples. O uso de bibliotecas amplamente adotadas no mercado (Spring Boot, Bootstrap, PostgreSQL) garante ampla documentação e suporte, enquanto a containerização com Docker viabiliza uma implantação padronizada e reprodutível em diferentes ambientes, incluindo o de homologação utilizado neste projeto.

O desenvolvimento do projeto seguiu práticas reconhecidas de Engenharia de Software, com versionamento contínuo do código-fonte por meio do Git e hospedagem centralizada no GitHub. Os commits foram organizados de forma incremental, cada um representando uma etapa ou funcionalidade específica do desenvolvimento, o que garante a rastreabilidade completa da evolução do projeto por meio do histórico de commits (Git Log).

## Disponibilização do Protótipo

**Repositório GitHub:** https://github.com/gsbad/ext-uninter-inclusao-digital

Todo o código-fonte do projeto encontra-se disponível publicamente neste repositório, incluindo o histórico completo de desenvolvimento. Isso permite acompanhar toda a evolução da aplicação, desde o planejamento inicial até a implementação final, por meio do Git Log.

**Protótipo publicado:** https://inclusao-digital.onrender.com/

A aplicação encontra-se publicada em ambiente de homologação utilizando a plataforma Render, permitindo a validação funcional do protótipo desenvolvido. Por se tratar do plano gratuito da plataforma, existem limitações inerentes ao serviço, especialmente em relação ao banco de dados PostgreSQL gratuito, cuja instância possui validade temporária de aproximadamente 30 dias, podendo ser reinicializada ou removida automaticamente pela plataforma, não garantindo persistência permanente dos dados cadastrados. Ressalta-se que essa limitação é exclusiva do ambiente gratuito utilizado para fins acadêmicos e de validação do protótipo, não representando uma limitação da arquitetura da aplicação nem da solução proposta.
